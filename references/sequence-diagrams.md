# PlantUML 时序图：生成、编辑与经验复用

用于新建或修改 `.puml` 时序图、学习时序图例、复用风格和布局，以及修正时序图反馈。默认交付可维护的 `.puml`、引用的本地样式文件和实际渲染的 PNG/SVG；用户指定 draw.io 时仍交付 `.drawio`，不静默转换格式。

## 工作流程

1. 明确场景、参与者职责、真实消息、成功/失败出口与输出介质。按 [learning.md](learning.md) 和 [library.md](library.md) 检索少量时序图经验，区分正负观察、个人偏好与验证状态。
2. 先列交互，再确定参与者顺序、阶段和条件。用稳定 ASCII 别名关联参与者，中文名称体现职责；编辑时保留未受影响的别名与消息含义。
3. 将样式放在独立 `.iuml`，业务消息与参与者顺序放在 `.puml`。先精简标签、分层注释和中文换行，再调整间距；实体增加时重新排列，内容过宽时拆分场景，不持续缩字。
4. 使用固定版本与字体实际渲染。按下表和 [quality-review.md](quality-review.md) 检查整体适屏和实际阅读尺寸，修正后重新渲染受影响视图。
5. 交付源码、所需样式、预览、渲染器版本、JDK/字体与检查范围。语法通过和导出成功分别记录，不能据此推断语义或美感通过。

## 专用规范

| 维度 | 规范与检查依据 |
| --- | --- |
| 参与者 | 用 actor 表示角色、participant 表示服务、database 表示存储、queue 表示消息中间件；形状不自动证明部署方式。名称体现职责，保持一致抽象层级，必要时拆视图 |
| 排列 | 按主调用方向、交互频率和实际关系排列，高频交互实体尽量相邻；角色→入口→编排→依赖/存储仅是候选顺序 |
| 间距 | 普通消息保持稳定节奏；阶段、条件与注释留出必要空间。先处理长标签、注释跨度和参与者顺序，再扩大间距，避免长箭头与无效留白 |
| 配色 | 使用克制的职责分类配色，弱化生命线、突出消息与阶段；颜色不创造同步、失败或所有权语义；具体色值可调整 |
| 阶段 | `== 阶段 ==` 组织阅读，不表示事务、同步屏障或原子性；事务与并发约束须来自事实并另作说明 |
| 消息 | 箭头上使用简短动作，字段、公式与完整约束放在就近 note 或正文；编号仅辅助引用，不代表跨线程全序 |
| 条件 | alt/else 标题使用短条件，复杂判断放注释；区分互斥、可选、循环与并行，嵌套过深时拆场景，保留真实分支与出口 |
| 激活与返回 | 激活区间体现实际执行与等待范围，返回对象对应真实调用方；需要明确的请求返回不能为排版省略，不凭激活条推断事务 |
| 同步与异步 | 同步调用通常用 `->`，回复用 `-->`，异步消息用 `->>`；异步不是虚线的同义词。MQ 的生产、入队确认、消费与业务完成分别表达，不能把 broker 当作同步代理 |
| 可维护性 | 独立样式、本地相对 include、固定渲染器及字体；调整 JDK/字体或样式后重渲染并更新证据。不要将流程图的圆角正交路由规则套到消息线上 |

## 候选风格与布局

以下来自用户描述的候选方向，不是对其本地图例的直接观察，也不代表读取了其三条个人候选记录。公开示例的验证范围仅覆盖本仓库虚构内容，不自动更新或升级个人资产的状态。

| 候选 | 保留方向 | 可调整部分与边界 |
| --- | --- | --- |
| 克制配色风格 | 白底、浅蓝服务、浅灰紫存储、浅黄注释、中性色消息和较弱生命线 | 色值、字号和间距按介质调整；不复制截图参数、不设为长期默认 |
| 分阶段编排布局 | 发起角色→入口服务→核心编排服务→依赖服务与存储；阶段帮助扫读 | 参与者顺序随高频交互重排；不同架构不强套编排中心，阶段不隐含事务 |
| 适配规则 | 先精简标签与注释，再扩大间距；增加实体时重排，过宽时拆图 | 不能删真实返回、分支或异步关系；拆图后保留场景之间的入口、出口与对应名称 |

共享样式见 [restrained.iuml](../examples/sequence/styles/restrained.iuml)，它是可运行的参考实现，不是用户默认。学习真实 `.puml` 时读取消息与 include 样式；从截图估计参数时标 visual_estimate。记录 sources.type=puml，模板 artifact 指向实际源码和所需样式，版本与适用边界沿用 [library.md](library.md)。

## 时序图 badcase 检查

| 可见问题 | 修正与验收条件 |
| --- | --- |
| 参与者间距过大 | 检查长标签、注释和参与者顺序；相关实体邻近，主路径易追踪，没有被空白拉长的无意义箭头 |
| 长公式挤占条件标题 | 标题保留短条件，完整判断就近说明；条件、分支与公式对应清楚，标题不撑宽条件框 |
| 注释撑宽全图或挡住消息 | 缩小注释跨度、换行或移至正文；消息和文字可独立阅读，注释不跨无关参与者 |
| 编号或中文换行不清晰 | 编号与消息分离，按职责词组换行；用实际中文字体检查文字完整、字号可读和编号归属 |
| 激活条与调用不一致 | 沿每个分支核对调用、等待和返回对象，激活开始结束有事实依据，不能为对齐随意延长 |
| 强加流程图圆角走线 | 保持时序消息的方向与箭头语义，正常跨列消息使用直线，自调用按时序表示，不另加正交绕行 |
| 为排版省略真实交互 | 与事实表逐项比对返回、分支和异步关系；复杂时拆图，完整交互仍能追踪 |

## 可运行示例与验证

所有场景均为虚构，使用同一份样式；容量检查与创建原子性是例中明确假设，不由阶段分隔推出。

| 源码 | 变化与检查重点 |
| --- | --- |
| [reservation.puml](../examples/sequence/reservation.puml) | 基础同步调用、自调用、存储访问、有效/无效及容量分支；四个参与者 |
| [reservation-long-labels.puml](../examples/sequence/reservation-long-labels.puml) | 改变中文名称、消息和注释长度，保持原交互；检查换行、宽度与编号 |
| [reservation-extra-participant.puml](../examples/sequence/reservation-extra-participant.puml) | 增加权限服务并就近排列；检查五个参与者的间距、拒绝出口与返回 |
| [reservation-branches.puml](../examples/sequence/reservation-branches.puml) | 改为幂等查询和重复返回分支；检查查询未命中后的并发说明与原子创建约束 |

在仓库根目录执行（Python 3.11+、Java 21、fontconfig、Noto Sans CJK SC）：

```bash
python3 scripts/render_sequence.py --install-only
python3 scripts/render_sequence.py
python3 scripts/check_sequence.py
python3 -m unittest discover -s tests -v
```

[运行锁](../scripts/plantuml-runtime.json) 固定 PlantUML 1.2026.9、官方 JAR URL 和 SHA-512。首次从 Maven Central 通过 HTTPS 获取并校验，缓存于忽略的 `.cache/plantuml/`，后续渲染离线复用。无需在线渲染服务，也无需为时序图安装 Graphviz。脚本记录实际 JDK 与字体，当前验证平台为 Linux/OpenJDK 21；不同 JDK 补丁、字体文件或平台不承诺逐像素一致，变更后须重验。

每次成功生成 PNG/SVG 和 render-manifest.json，记录源文件、样式、运行锁与产物哈希；渲染清单明确保留语义/视觉检查未执行状态，语义和视觉复查另记在 [验证记录](../docs/sequence-validation.json)。失败应返回非零，不将 PlantUML 错误图片或旧预览当作成功证据。保留未执行、失败和已通过的区别。

本次覆盖同步基础场景及三个变体，**MQ 异步生产/消费、并发、超时/重试等场景仍待单独补充和验证**。不据此声称时序图的全部交互类型已实现；用户本地三条候选记录仍以其真实索引和证据为准。

语法与工具说明：[PlantUML sequence diagrams](https://plantuml.com/sequence-diagram)、[command line](https://plantuml.com/command-line)。具体参数以固定版本的 `--help` 为准。
