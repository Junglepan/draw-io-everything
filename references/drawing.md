# draw.io 绘图基线与执行

## 准备

明确核心问题、读者、图种与粒度、事实来源、输出尺寸。已知内容直接采用；只问会改变图种、语义或边界的缺口。读取 library/index.json，选择匹配的模板和样式；参照 library.md 的版本标识记录到交付说明。

同时按图种与结构检索少量相关正负经验。例如跨区、多分支、回流流程，优先读取这些结构对应的缺陷案例；提取本次要保留的设计、要防止的问题与可核对的验收条件。区分用户明确偏好和未验证策略，资产库为空时使用基线与 [quality-review.md](quality-review.md)，不虚构历史经验。

默认交付原生 `.drawio` 和 PNG 预览；按用途补 SVG/PDF。优先现有可用工具，不自动安装软件或声明未发现的 MCP 接口。执行前核对工具帮助和版本；桌面端通常支持 `-x -f png -o <preview> <source>`，仅使用当前版本确认支持的参数。macOS 可检查 `/Applications/draw.io.app/Contents/MacOS/draw.io`。

## 内容与视觉分离

先建立节点、关系、分组和标签，再映射模板槽位与样式。模板需适配事实，不能反过来增加虚构系统或删除重要关系。模板固定特征保持，变量按内容调整；超出容量按 growth_rules/overflow_rules 扩展或拆页。

按“检索经验 → 关系组织 → 布局与通道 → 连线 → 渲染 → 修正复查”推进：先确定主链、分支、汇合、回流和跨区依赖，再安排模块与分组位置。节点、标签、连线共同占据布局空间；给端口、转弯、箭头末端和跨区路径预留通道。若走线只能挤缝或反复绕行，回到分组与布局，不只追加途经点。能清晰直连时保持直线，圆角用于确需转弯的正交路径。

基线只是空库或缺少对应 token 时的初始选择，不是用户偏好或行业强制要求：

- 使用 8 或 10 单位网格；组间距大于组内距，容器内边距通常从 16–24 单位起步。
- 节点文字通常从 14–16 起步，标题从 20–24 起步；根据最终尺寸和中文字体实际渲染调整。不要靠缩小文字容纳更多内容。
- 同类图形和边框一致；语义不同的图形不为整齐而统一。深色、浅色和多色都可采用，关键是可读性与稳定含义。
- 同层对象对齐，重复元素有统一节奏；必要时按文字调整宽高，保护标签换行。
- 连接器附着节点/端口；一般优先圆角正交布线，减少无关节点穿越、交叉与线段堆叠。时序图等遵守各自布局。
- 主流程连续，异常路径有明确条件；边标签贴近对应边且不压线。关键关系用具体动词/协议表达。
- 图标从真实可用库取值；不猜 `mxgraph.*` 名称。无合适图标时用带明确标签的基础形状。
- 标题写明范围，必要时标环境与版本；图例解释自定义符号和颜色，不依赖颜色作为唯一信息载体。

绘图前和导出后按 [visual-design.md](visual-design.md) 检查比例、疏密、留白、线条及色彩语义。工具细节服务于这些目标，不以使用复杂图形作为能力证明。

## 原生 XML 最小约定

每页使用 `mxGraphModel/root`；保留根 cell `0` 和默认层 `1`，业务节点不占用它们。每个 cell 在本页内有唯一 id，父级与边引用有效。节点 geometry 给出尺寸与位置；容器子坐标相对父级。边使用真实 source/target 和 `<mxGeometry relative="1" as="geometry"/>`，途经点通过 points 数组表达。

对 XML 和标签做正确转义；保留原有页、图层、元数据和稳定 id。不要将整张图片作为可编辑图的替代品。局部修改只移动必要对象；大幅更改布局才重排整页。

## 验证

结构检查：XML 可解析、id 唯一、父级与端点有效、几何尺寸合理。可用解析器执行这些确定性检查；没有完整 linter 时明确已检查的子集。

语义检查：节点和关系符合事实与所选图种；条件、基数、边界和消息类型正确。风格不能覆盖标准箭头。基础流程图通过不代表 BPMN 合规。

视觉检查：实际在 draw.io 打开或渲染，按 [quality-review.md](quality-review.md) 的顺序复查语义、可读性缺陷、审美质量。整体适屏检查层级、密度、留白和主路径；实际阅读尺寸检查文字、标签、端口与转折。XML 坐标检查无法覆盖自动路由、字体和文字溢出，XML 合法或导出成功不代表美观通过。优先修复可观察缺陷，不根据想象反复改图。

完成修复后重新检查受影响页。渲染失败先定位错误，再选择可用编辑器或交付源文件并注明未渲染；不要无限重试，不声称通过。当前 skill 没有自带自动排版引擎或全面标准合规验证器。

每项修正保留问题区域、策略、验收条件与前后产物；重渲染后追踪受影响的完整路径、相邻分支与跨区连接，检查是否引入新遮挡或语义变化。最终检查必须对应最终源文件，旧预览结论不得沿用。记录实际执行与未执行的检查；只有改变标签长度、节点数量或分支结构后仍有效，才能扩大经验的复用范围。当前图修复通过不等于通用布局已验证，也不代表用户已经认可整体美感。
