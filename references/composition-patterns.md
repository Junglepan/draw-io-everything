# 构图与局部模式候选

这些是带条件的设计方法，不是强制布局或完整标准。可组合使用，具体配色、尺寸与朝向需适配当前内容。除仓库已有明确验证记录的案例外，不声称已做迁移验证。

## 构图范式

| 范式 | 组织方法与用途 | 适用边界 |
| --- | --- | --- |
| 主入口与渐进深入 | 突出入口，子项、来源与辅助材料靠近主体；用于文档导航、知识入口与职责地图 | 空间邻近不证明调用顺序或数据血缘 |
| 阶段化系统协作 | 按阶段分区，区内组织主要交接，跨区留走线通道；约束放就近辅助区 | 阶段带不等于责任泳道，跨带对齐不代表同一责任方；复杂交互另用时序图展开 |
| 责任 × 阶段矩阵 | 两轴分别表示责任方与阶段，同时比较谁做、何时做 | 空格可表示无动作；责任过多或跨阶段往返频繁时拆图或改为单轴泳道 |
| 层级—能力—事实归属 | 行带表达层级、能力与职责，以及权威数据或结果归属 | 用于解释架构边界；排列不自动表示调用依赖，事实归属必须有依据 |

## 可组合的局部模式

| 模式 | 解决的阅读问题 | 关键约束 |
| --- | --- | --- |
| 主入口强调 | 快速找到起点 | 最强对比留给主要对象；不把视觉起点误作执行起点 |
| 主标题 + 次级说明 | 同时展示名称、职责与必要细节 | 标题独立可读，细节不抢焦点 |
| 跨区连线通道 | 降低长线穿越与交接追踪成本 | 布局时预留，端点与方向明确 |
| 就近辅助卡 | 展示约束、策略与结果说明 | 与执行节点区别，不接入虚构的控制流 |
| 角色与变化分开编码 | 区分对象是什么、发生了什么变化 | 两种编码分别解释，改造标记不代表完成状态 |
| 同源分支局部展开 | 降低一对多关系的追踪成本 | 共享走向不能暗示不存在的汇聚、总线或同步语义 |
| 出口条件条 | 说明阶段何时算完成 | 条件须有事实依据，不能用颜色替代条件文字 |

复用局部模式不必继承原图整体布局。节点增长时先检查是否仍解决原阅读问题，再调整分组、走线或视图粒度。
